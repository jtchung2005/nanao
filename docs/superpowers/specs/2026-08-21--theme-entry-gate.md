# 主題選擇入口 + 圖譜介面簡化 — 設計規格

日期：2026-08-21
狀態：待實作（先做測試分支，本地預覽確認後才 push GitHub）

## 背景

使用者操作前測發現：目前網站一進來就把全部 339 個節點一次顯示，測試者普遍反應資訊過載。目標是仿照常見 App 的「開場選興趣主題」模式，讓使用者先選想探索的主題，再進圖譜看聚焦後的內容；同時簡化圖譜畫面上目前用不太到的操作面板。

## 1. 主題分類

現有資料的 `group` 欄位有 14 種原始分類，且有重複／不一致（如「地點」vs「空間」、「政府機關」vs「政府機構」）。這些分類無法直接對應使用者想要的敘事式主題（如「美食」「當地英雄人物」），因為一個主題常橫跨多個原始分類。

**做法**：新增一份獨立的「節點 → 主題」對照表（JSON），用「現有分類 + 關鍵字比對節點名稱與介紹文字」自動產生初版，不改動 `data/graph.json` 原始資料。使用者審核後再手動微調錯分的節點。

**草案主題（8 類，經使用者確認顆粒度 OK）**：

| 主題 | 對應內容 |
|---|---|
| 泰雅人物與英雄故事 | 頭目、耆老、青年、學者等人物、族群 |
| 部落遷徙與歷史事件 | 遷村、理蕃、討伐等歷史事件 |
| 尋根活動與文化傳承 | 尋根之旅、織布課程、文物展、家屋 |
| 段木香菇產業與林下經濟 | 產業、菌種、樹種、批發零售 |
| 在地美食與飲食文化 | 小米醃肉、刺蔥、健康餐盤等飲食相關物件 |
| 健康與日夜節律研究 | 睡眠、光照、慢性病等健康議題 |
| 部落空間與地景 | 部落、聚落、據點 |
| 在地組織與計畫 | 政府機關、非營利組織、私人企業、大學（前 7 類分類不到的節點兜底） |

每個節點可能同時屬於多個主題（例如某個菇農人物節點，同時屬於「泰雅人物」與「段木香菇產業」）。

## 2. 入口畫面（每次進站都會出現）

- 全螢幕蓋板，8 個主題卡片，**可複選**（chip / card 樣式，選中有視覺標示）
- 底部兩個按鈕：「進入圖譜」（至少選 1 個主題才能按）、「跳過，看全部」
- 視覺風格沿用現有紙質感設計語言（`src/styles/paper.css` / `tokens.css`）

**出現時機**：不用 localStorage 記憶，每次重新整理網站都會出現（跟第一次進入導覽的判斷邏輯分開）。

## 3. 進圖譜後的畫面調整

**拿掉**：
- 左側「強調」分群側欄（`GroupSidebar.jsx`，點類別名稱高亮節點群的那個）
- 底部整個面板（`TimelineSlider` 時間軸 + `Legend` 類別勾選 + `RelationFilter` 關係勾選）

**保留不動**：
- 上方 TopBar／搜尋列
- 右上 `GraphControl`（字體大小／節點大小／施力強度）
- 左下 `Minimap`
- 點節點跳出的 `InfoCard`

**新增：底部主題 nav bar**
- 顯示目前「沒被選中」的其他主題 chip，外加一個「顯示全部」chip
- 點某個主題 chip → **切換**（不是疊加）成只顯示該主題的節點，nav bar 內容跟著更新（該主題移出，換上原本被選中、現在沒選的主題）
- 點「顯示全部」→ 清空主題篩選，顯示完整 339 節點的圖譜

**篩選邏輯**：既有的 `mg`（類別）／`mr`（關係）／`years`（年份區間）URL 篩選機制維持在程式碼裡，但 UI 上不再有勾選介面，效果上永遠是全開（不限制）。主題篩選是獨立於 `mg`/`mr` 之上的新篩選層，直接用主題對照表比對節點 ID。

## 4. 與現有「首次進入導覽」的整合

- 只有帳號**第一次造訪**（用現有 `localStorage.nanao_tour_seen` 判斷）才會在選完主題、進圖譜後**緊接著**跑導覽
- 之後每次重整只會看到主題選擇畫面，不會再跑導覽
- 現有導覽步驟中，介紹左側分群側欄（`tour-sidebar` / `tour-cat-*`）跟時間軸（`tour-timeline`）的步驟需要移除或改寫，因為對應的 DOM 元素會被拿掉；可視情況加一步介紹新的底部主題 nav bar

## 5. 測試版本交付方式

1. 開一個新 git branch（不動 `main`），在上面實作這個功能
2. 本地跑 `npm run dev`，起一個本地網址（如 `http://localhost:5173`）給使用者直接在自己的瀏覽器打開操作
3. 使用者確認畫面與互動沒問題後，才會決定是否 push 到 GitHub / 合併回 `main`（正式網站不會在這之前被更動）

## 範圍外（本次不處理）

- 不修改 `data/graph.json` 原始資料或 Excel 資料管線
- 不清理 `meta_mapping.py` 裡另一套（目前未使用的）7 分類邏輯
- 不處理資料本身的雜訊節點（如 `自動增加` 的顏色圖例節點）
